ANNOCATE - SPAN & ANNOTATION ROADMAP & TODO
================================================================================

[X] 1. FIX: Span selection & labeling not registering in answer form
    - Cause: In JobRunner.tsx, SpanAnnotationProvider was only wrapping UnitFields
      (the text display), while the bottom docked answer form (questionElement)
      was rendered outside it. SpanAnswerField called useSpanAnnotation() which
      returned null, causing "No spans selected yet" and submitting empty spans.
    - Solution: Wrapped both UnitFields and questionElement inside SpanAnnotationProvider.
      Spans now immediately appear in SpanAnswerField with live counts, badges,
      remove buttons, and proper submission to JobServer on Done/Next.

[X] 2. Word vs. Character Level Selection Mode
    - Implemented snapToWord algorithm: snaps selection start backwards to the
      beginning of the word and end forwards to the end of the word, trimming
      trailing/leading whitespace.
    - Added selectionMode ("word" | "character") to SpanTypeSchema in contracts.
    - Added "Default Selection Mode" dropdown to the Visual Codebook Editor in VariableTypeForm.tsx.
    - Added coder toggle in the UI (both in the docked answer bar and hotkey 'w')
      allowing annotators to toggle between whole-word and character-level selection.

[X] 3. Keyboard Navigation Support
    - Number hotkeys (1-9): When a text selection is made, pressing 1 through 9
      immediately assigns that code without needing to click.
    - Enter key: Assigns the first code.
    - Esc key: Cancels the pending selection or closes the popover.
    - 'w' key: Toggles between Word-level and Character-level selection mode.
    - Backspace / Delete: Removes the most recently added span (or focused span).
    - Shift + Arrow keys: Native keyboard text selection triggers code picker.

[X] 4. Multiple Overlapping Spans on Same Text
    - Removed previous overlap rejection.
    - Implemented boundary cut-point segmentation in SelectableText:
      Text is partitioned by all unique span starts and ends.
    - Overlapping segments are styled with a multi-color vertical gradient
      and multi-color bottom border (derived from each overlapping span's code color).
    - Hover title displays all overlapping codes (e.g., "[actor, positive]").

[X] 5. Overlapping Span Management Popover
    - When clicking a segment covered by multiple spans, an interactive
      popover/bar opens displaying each individual span badge with a remove [x] button.
    - Single-span segments still allow direct 1-click removal.


================================================================================
ANALYSIS OF OLD IMPLEMENTATION (/old) & COMPARISON WITH MODERN ANNOCATE
================================================================================

1. Token-Based vs. Character-Offset Architecture:
   - In /old: Every single word/punctuation was pre-tokenized into a discrete DOM
     <span ref={...} data-token-id={i}> element.
     * Pros: Trivial word boundary detection (just integer token ranges [from, to]).
     * Cons: Massive DOM overhead on long texts (1,000+ words meant 1,000+ DOM nodes
       and refs), fragile rendering with markdown/formatting, rigid token boundaries
       preventing sub-word or arbitrary character annotations (e.g. compound words,
       URLs, morphology, CJK languages).
   - In modern Annocate: Clean character-offset model ([offset, length, text]) with
     DOM TreeWalker range extraction and snapToWord boundary logic.
     * Benefits: Zero DOM bloat, high performance on long texts, flexible word or
       character precision, clean JSON export.

2. Code Assignment UI (Floating Portal vs. Docked/Inline):
   - In /old: Used AnnotationPortal.tsx with a setInterval loop trying to measure
     DOM elements and keep a floating box on-screen above the token.
     * Quirks: Glitchy on mobile/touchscreens, screen overflow clipping, jumping.
   - In modern Annocate: Responsive inline assignment bar with 1-9 hotkeys directly
     under the selection, paired with the persistent thumb-friendly bottom dock.

3. Features from /old to Consider for Future Tasks:
   - Feature A: Code Search Filter in Code Picker (Search-as-you-type)
     * In /old: ButtonSelection.tsx had a search input if there are many codes.
     * Modern Plan: If a span variable defines > 8 codes, display a search input
       in the code assignment popup (or cmdk-style palette).
   - Feature B: Span Re-editing (Edit Mode)
     * In /old: Clicking a span opened a menu: [Change Code], [Expand/Shrink Range], [Delete].
     * Modern Plan: In the overlapping popover or single span click, allow picking
       a different code to reassign it without having to re-select the text.
   - Feature C: Relation Annotations (Visual Connecting Arrows)
     * In /old: RelationArrows.tsx used SVG bezier curves over the text between
       two tokens with arrowheads and relation labels.
     * Discussion needed: Drawing SVG curves between dynamic text ranges across
       responsive mobile screen resizes is complex. We should discuss whether
       relations are primarily drawn visually or via sequential selection
       (e.g., select source span -> select target span -> assign relation).
